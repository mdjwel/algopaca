# Implementation Plan & Walkthrough in Bengali (Bangla) Policy

Whenever planning tasks, proposing architectural designs, or documenting completed work in this project, the **Implementation Plan** (`implementation_plan.md`) and **Walkthrough** (`walkthrough.md`) artifacts MUST be authored in **Bengali (Bangla)**.

## 1. Scope & Core Requirement

- **Bengali Language Requirement**:
  - All narratives, summaries, background descriptions, rationale, open questions, task breakdowns, checklists, and verification explanations in `implementation_plan.md` and `walkthrough.md` must be written in clear, natural, and professional Bengali.
- **Technical Terms & Code Elements**:
  - Technical terms, code symbols (function names, class names, variables), terminal commands, file paths, URLs, and code snippets must remain in English using appropriate formatting (`inline code` or fenced code blocks) to maintain precision.
  - File links must always follow GitHub markdown format with `file:///` scheme (e.g., `[filename.py](file:///path/to/filename.py)`).

## 2. Implementation Plan Guidelines (`implementation_plan.md`)

When creating or updating an Implementation Plan:
1. **Goal & Overview (লক্ষ্য ও সারসংক্ষেপ)**:
   - Explain the objective, background context, and what the changes achieve in Bengali.
2. **User Review & Open Questions (ব্যবহারকারীর পর্যালোচনা ও প্রশ্নাবলী)**:
   - Clearly highlight breaking changes, architectural choices, and design trade-offs in Bengali using GitHub alerts (`> [!IMPORTANT]`, `> [!WARNING]`).
   - List any open questions or choices that require the user's feedback in Bengali.
3. **Proposed Changes (প্রস্তাবিত পরিবর্তনসমূহ)**:
   - Group files logically by component or layer.
   - Use standard tags (`[NEW]`, `[MODIFY]`, `[DELETE]`) with file links.
   - Describe what will change in each file and why in Bengali.
4. **Verification Plan (যাচাইকরণ ও টেস্টিং পরিকল্পনা)**:
   - Detail automated test commands and manual verification steps in Bengali.

## 3. Walkthrough Guidelines (`walkthrough.md`)

When creating or updating a Walkthrough after completing work:
1. **Summary of Work (সম্পন্ন কাজের সারসংক্ষেপ)**:
   - Provide a concise summary of what was accomplished and fixed in Bengali.
2. **Key Changes & Implementation Details (মূল পরিবর্তনসমূহের বিবরণ)**:
   - Describe each major change, design decisions, and file updates in Bengali.
3. **Verification & Testing Results (যাচাইকরণ ও পরীক্ষার ফলাফল)**:
   - Document the results of tests, command outputs, server health checks, and UI validations in Bengali.
